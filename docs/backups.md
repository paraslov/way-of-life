# Бэкапы

Решение D17: сверх встроенного PITR у Neon — дамп на собственную машину, в папку
`~/way_of_life/backups`. Облачного хранилища для дампов нет: медицинские данные не
копируются ни в какой третий сервис.

## Снять бэкап

1. В `.env.local` задать `BACKUP_DATABASE_URL` — **прямой** (не `-pooler`) URL базы
   Neon. Лучше отдельная read-only роль; подойдёт и владелец.
2. Запустить Docker и выполнить:

```bash
pnpm db:backup
```

Скрипт [`scripts/backup.mjs`](../scripts/backup.mjs):

- запускает `pg_dump --format=custom --no-owner` в контейнере `postgres:18-alpine`
  (локальный клиент PostgreSQL не нужен; URL передаётся переменной окружения, а не аргументом);
- проверяет дамп через `pg_restore --list`, иначе удаляет его;
- пишет `way-of-life-<UTC-время>.dump` с правами `600` в папку с правами `700`;
- хранит `BACKUP_KEEP` последних файлов (по умолчанию 26 ≈ полгода еженедельно).

Настройки: `BACKUP_DIR` (по умолчанию `~/way_of_life/backups`), `BACKUP_KEEP`.

Диск должен быть зашифрован (FileVault) — в дампе все данные о здоровье.

## Восстановить

В пустую базу (новая ветка Neon или локальный контейнер):

```bash
docker run --rm -i postgres:18-alpine pg_restore --no-owner --exit-on-error -d "<url>" < ~/way_of_life/backups/way-of-life-….dump
```

Перед этим в целевой базе должна существовать роль `way_of_life_app` (SQL — в
README), иначе её GRANT-ы не восстановятся. Проверено 28.09.2026: локальный дамп
восстановлен в чистую базу без ошибок, RLS и `schema_migrations` на месте.

## Расписание

Пока вручную. Автозапуск раз в неделю (launchd на macOS) — по желанию, не настроен.
